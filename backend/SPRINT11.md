# Спринт 11: наскрізні перевірки backend

Основа: [ЛР1, розділи 4, 5, 7.2 та 8.1](../ЛР1_SkillSwap_Специфікація_вимог.pdf).
Спринт 11 охоплює приймання всього MVP: FR-01—FR-15 та NFR-01—NFR-05,
NFR-07—NFR-12. Цей документ описує серверну частину перевірок і явно відокремлює
критерії, для яких потрібен браузер або участь людей.

## Що запускають тести

Новий пакет [`e2e`](e2e/) збирає і запускає `cmd/api`, `cmd/db` та `cmd/loadtest`.
Клієнти надсилають HTTP-запити через TCP до окремого процесу API; він використовує
справжні сервіси, pgx, PostgreSQL та SMTP-адаптер. Локальний SMTP-приймач приймає
реальні листи, розкодовує MIME і дістає одноразові посилання. Зовнішньої доставки
немає. Mailpit залишається засобом ручної перевірки листів.

Для кожного тесту створюється нова БД `skillswap_e2e_<унікальне число>`,
застосовуються всі Goose-міграції та `seeds/integration.sql`. Після тесту процес
API зупиняється, з'єднання закриваються, створена БД видаляється. База застосунку
з `backend/.env` не використовується. Тести не запускаються паралельно між собою.

SQL використовується лише для підготовки та незалежної перевірки результатів:
призначення адміністратора, перенесення часу посилання/заняття, ін'єкції помилки,
перевірки хешів, кількості записів і знеособлення. Доменні дії виконуються через
HTTP. Перенесення заняття в минуле дозволяє перевірити підтвердження без очікування
реальної години.

Наявний `internal/api/mvp_test.go` зберігається як регресійний MVP-сценарій для
пам'яті та PostgreSQL. Новий пакет доповнює його перевіркою процесів, SMTP,
критеріїв відмови та експлуатаційних сценаріїв.

## Запуск

Команди виконуються з `backend/`. Потрібні Go відповідно до `go.mod` і PostgreSQL
15+ з ICU та утилітами `initdb`, `pg_ctl`, `pg_dump`, `pg_restore`.
`initdb` запускається від звичайного користувача ОС, не від Unix root.

Рекомендований варіант у PowerShell:

```powershell
$env:E2E_PG_BIN = 'C:/Program Files/PostgreSQL/18/bin'
go test ./e2e -v -count=1 -timeout 5m
```

Шлях має вказувати на встановлені PostgreSQL-утиліти. Набір сам створює тимчасовий
кластер у системному каталозі тимчасових файлів, з ICU `uk-UA`, вільним портом і
прослуховуванням лише `127.0.0.1`. Після прогону він зупиняє цей кластер і видаляє
його файли. PostgreSQL-служба, Docker, запущений API та Mailpit не потрібні.

Для вже запущеного локального PostgreSQL:

```powershell
$env:E2E_DATABASE_URL = 'postgres://postgres:postgres@127.0.0.1:5432/postgres?sslmode=disable'
$env:PG_BIN = 'C:/Program Files/PostgreSQL/18/bin'
go test ./e2e -v -count=1 -timeout 5m
```

У цьому варіанті роль повинна мати `CREATEDB`, а сервер — Unicode-aware locale
для українського пошуку. `E2E_PG_BIN` не має бути задана одночасно: вона має
пріоритет. Віддалені адреси та підміна адреси/БД через параметри URL відхиляються.
Сервер не перезапускається; `TestE2ERestartPersistence` позначається `SKIP`, оскільки
набір не володіє цим кластером. Для повного серверного приймання потрібен перший
варіант.

Без `E2E_PG_BIN` і `E2E_DATABASE_URL` звичайний `go test ./...` компілює пакет,
але пропускає його зовнішні сценарії. Наявні unit-тести працюють як раніше.
`TEST_DATABASE_URL` належить старим інтеграційним тестам і не вмикає цей пакет.

Повний навантажувальний тест, без скорочення тривалості:

```powershell
$env:E2E_LOAD = '1'
go test ./e2e -run '^TestE2ELoad$' -v -count=1 -timeout 15m
```

Окремий 60-хвилинний прогін стабільності:

```powershell
$env:E2E_SOAK = '1'
go test ./e2e -run '^TestE2ESoak$' -v -count=1 -timeout 65m
```

Усі серверні сценарії, включно з обома довгими:

```powershell
$env:E2E_LOAD = '1'
$env:E2E_SOAK = '1'
go test ./e2e -v -count=1 -timeout 75m
```

Кожна з цих команд потребує попередньо заданої `E2E_PG_BIN` або
`E2E_DATABASE_URL`. `-count=1` виключає використання кешованого результату.
Для протоколу можна додати `-json` і зберегти вивід у файл поза Git.

## Протокол перевірки

Стенд поточного прогону: Windows amd64, 12 логічних процесорів, 31.7 GiB RAM,
Go 1.27.3 (модуль декларує Go 1.26.0), PostgreSQL 18.0 з ICU `uk-UA`.
API, PostgreSQL, SMTP-приймач і клієнти працюють локально. Накопичувач —
KINGSTON SNV3S1000G, Windows `Get-PhysicalDisk` визначає його як SSD.

Результати 29 жовтня 2026 року:

`SKIP` не означає виконаний критерій. Локальні протоколи, PostgreSQL-утиліти,
кластер і резервні копії не додаються до Git.

Наявність цих backend-тестів не є підтвердженням повного приймання спринту 11:
для нього також потрібні зазначені браузерні вимірювання, 60-хвилинний прогін,
перевірка запуску всього стеку та протокол тестування з п'ятьма учасниками.
