# Sprint 11 — перевірки frontend

Джерело критеріїв — `../ЛР1_SkillSwap_Специфікація_вимог.pdf`, розділи 4, 5 та 8.
FR-16—FR-23 і NFR-06 не належать до приймання локального MVP.

## Запуск

Команди виконуються з `frontend/` після `npm ci`.

```bash
npm run build
npm test
npm run test:browser
npm run test:browser:matrix
npm run test:acceptance
npm run lint
npm run format:check
```

`test:browser` запускає регресійні frontend-сценарії на production Next.js,
порт 3100. Go API та Mailpit підміняються ізольованими fixtures; ці перевірки
не засвідчують роботу PostgreSQL, SMTP, серверних прав чи транзакцій.
Модульні тести перевіряють API-клієнти, валідацію, URL, повідомлення та формати.

## NFR-02 — вимірювання на реальному стеку

`npm run test:acceptance` сам запускає production Next.js, Go API та власний
тимчасовий PostgreSQL-кластер, застосовує міграції й `seeds/integration.sql`.
Чинний `backend/.env` не визначає цільову БД цього стенда: її URL завжди
перевизначено адресою нового loopback-кластера. Сервери зупиняються після
прогону; видаляється лише створений стендом каталог `backend/.local/browser-acceptance-*`.
Порти 3000 і 8080 мають бути вільні. Наявний сервер не перевикористовується.
SMTP не потрібен: тестові акаунти вже мають підтверджену пошту.

Потрібні Go та PostgreSQL 15+ з ICU. Шлях до PostgreSQL-утиліт задається через
`E2E_PG_BIN` або `PG_BIN`; також знаходиться локальний комплект
`backend/.local/postgres-tools/pgsql/bin` або утиліти з PATH.

- Рівно 30 повних завантажень: по 10 сторінок `/main`, `/search`, `/profile`.
  Відлік починається перед навігацією. Завершення вимагає даних студента,
  фактичної картки партнера чи значень профілю, а також двох кадрів рендерингу.
  Поява оболонки або skip-link не завершує вимірювання.
- Без штучного обмеження мережі; один worker. Потрібно щонайменше 29/30
  завантажень за ≤ 3000 мс і p95 ≤ 3000 мс.
- Два окремі браузерні контексти входять через форми. Нове унікальне повідомлення
  надсилається через UI та має з'явитися в іншому відкритому чаті за ≤ 10 с
  через стандартний polling 5 с, без навігації чи reload отримувача.
- Кожен вимір і фактична версія браузера додаються до звіту Playwright.
  Звіти: `test-results/acceptance.json` та `playwright-report/acceptance/`.
  Часові бюджети не повторюються автоматично після невдалого результату.

`nfr.spec.mjs` зберігає окремий швидкий вимір рендерингу з підміненим API;
він явно позначений як frontend-регресія і не замінює приймальний прогін.

## NFR-10 — клавіатура та адаптивність

`keyboard.spec.mjs` проходить реєстрацію, підтвердження пошти, вхід,
чотири кроки onboarding, пошук, профіль кандидата й створення запиту.
Взаємодія використовує Tab, Enter, Space і текстове введення клавіатурою;
перевіряються видимий фокус, помилки форм, skip-link, Escape та повернення
фокусу після діалогу. Mailpit і API у цьому наборі підмінені.

`keyboard-exchange.spec.mjs` готує активний план через fixture, потім перевіряє
клавіатурою зміну умов заняття, погодження, підтвердження проведення,
двостороннє завершення й взаємні відгуки. Підготовка даних не є дією UI.
Обидва набори перевіряють українську мову й відсутність горизонтального
переповнення на 360, 768 і 1440 px. Додатковий NFR-набір включає 1920 px.

## NFR-11 — браузери та користувацьке приймання

Матриця містить окремі проєкти `chrome`, `edge`, `firefox`.
Chrome та Edge мають бути встановлені. Firefox встановлюється командою
`node node_modules/@playwright/test/cli.js install firefox` і є збіркою Playwright.
Звіти з фактичними версіями: `test-results/matrix.json` та `playwright-report/matrix/`.
Відсутній або несправний браузер спричиняє помилку, а не прихований SKIP.

Для додаткових попередніх версій задайте шляхи до виконуваних файлів:
`PLAYWRIGHT_CHROME_PREVIOUS`, `PLAYWRIGHT_EDGE_PREVIOUS`,
`PLAYWRIGHT_FIREFOX_PREVIOUS`. Це додає проєкти `*-previous` до обох матриць.
Firefox має бути сумісною з Playwright збіркою. Шлях не завантажує браузер
і не засвідчує його стабільний канал: фактичні версії та відповідність двом
останнім стабільним випускам потрібно звірити на дату приймання.

Стан приймання з п'ятьма реальними учасниками: **пропущено за рішенням користувача**.
Автоматизоване проходження не зараховується за результати цих учасників.
