## Запуск

Команди виконуються з `frontend/`. Спочатку встановіть залежності через `npm ci`.
Playwright потребує встановленого Chromium (`npx playwright install chromium`)
або наявного Chrome/Edge, який конфігурація знаходить автоматично.

```bash
npm run build
npm run test:browser
```

Окремо доповнення першого блоку (25 сценаріїв):

```bash
npm run test:browser -- auth-profile.requirements.spec.mjs discovery.requirements.spec.mjs
```

Разом з попереднім покриттям цих вимог:

```bash
npm run test:browser -- auth-profile discovery-exchange discovery.requirements
```

`playwright.config.mjs` запускає production-збірку через `next start` на
`http://127.0.0.1:3100`; порт має бути вільний. Браузерні контексти ізольовані,
часовий пояс — `Europe/Kyiv`, один worker. Тести не потребують `.env`, Go API,
PostgreSQL чи запущеного Mailpit і не змінюють їхні дані.

## Межі перевірки

Це наскрізні **сценарії frontend**: справжній браузер, Next.js, React, форми,
навігація, HTTP-запити та відображення відповідей. API й вебінтерфейс Mailpit
підміняються через `createMvpWorld` і `page.route` / `context.route`.
Кожен тест створює власні дані; взаємодія двох студентів використовує окремі
браузерні контексти зі спільною моделлю API. Підготовка акаунта й початкової
сесії через fixture не є перевіркою реального входу; там, де вхід є предметом
сценарію, він виконується формою.

Успішний прогін не засвідчує роботу повного ланцюжка браузер → Go → PostgreSQL →
SMTP. Зокрема, `invalid_token` у тесті простроченого посилання задає відповідь
сервера: тест перевіряє реакцію інтерфейсу, а не серверний TTL. Перевірка
чужого профілю підтверджує відсутність редагування у UI та використання
`me/profile`; серверну авторизацію треба перевіряти окремо.

Реальний Mailpit, збереження після перезапуску сервера, серверна валідація,
правила пошуку/сортування, SQL, bcrypt, транзакції, резервне копіювання та
навантаження потребують перевірок реального локального стенда. Частина таких
перевірок уже є в `backend/e2e/` та інтеграційних тестах; їх запуск описаний у
`backend/README.md`. Вимірювання на підмінених відповідях у `nfr.spec.mjs`
не є результатами приймання швидкодії Go API. Перевірка зручності з п'ятьма
учасниками та двох версій кожного браузера також потребує окремого протоколу.
